# 베들레헴 환경 1차 구현 · 2026-11-05

## 범위와 현재 상태

이번 작업은 환경 제작과 기존 탐험 기능 연결이다. NPC, 주요 인물, 시네마틱, 음성, 음악 및 10~15분 분량의 사건 콘텐츠는 구현하지 않았다. 영화 수준의 최종 아트 완성본으로 간주하지 않는다. 기존의 단순 마리아·요셉·아기 도형을 새 환경에 재사용하지 않았다. 현재 탄생 장소에는 비어 있는 구유와 조명만 있다.

운영 사이트에는 배포하지 않았다. 사용자 확인 후 다음 단계를 진행한다. `/walk/` 파일은 작업 전후 SHA-256 비교에서 동일했다. `journey/`와 `walk/`는 작업 시작 시부터 Git 추적 대상에 포함되지 않은 로컬 디렉터리였다. 향후 배포 시 `walk/vendor/three.module.js`와 해당 라이선스도 저장소에 있어야 한다.

## 구조 분석과 구현

기존 스택은 빌드 과정 없는 ES module + 로컬 Three.js 0.170.0이다. 기존 양 모델, 키보드·터치 이동, A* 경로, 지도, 33개 성경 이야기, 기록 저장을 사용한다. 라이브러리나 외부 모델·이미지를 추가하지 않았다.

- `worlds/bethlehem.js`: 베들레헴 방문 시 동적 import. 지형·24채 주택·시장·입구·탄생 장소·들판·전망대, 자체 생성 재질, 환경 애니메이션과 카메라 장애물 보정.
- `app.js`: 월드별 지형 높이·탐험 반경·이야기 위치 연결. 높낮이가 있는 지형에서도 경로 도착을 XZ 평면에서 판정. 비동기 월드 전환 경합 방지. 지오메트리, 재질, 텍스처, 인스턴스, 그림자 리소스 정리.
- `index.html`, `style.css`: 베들레헴의 다섯 탐험 목적지와 모바일 레이아웃.
- 다른 10개 월드는 기존 생성 코드·이야기·조작을 유지.

주택은 크기·층고·옥상 구조·돌계단·문·창문을 달리했다. 갈라지는 흙길은 지형 높이를 따르며, 별과 먼 언덕·안개·달빛·따뜻한 국소 조명으로 깊이를 구성했다. 올리브 수관, 시장 천막, 들판 풀, 등불 밝기가 움직인다. 움직임 줄이기 설정에서는 환경 움직임을 멈춘다.

이 환경은 성경 이해를 돕는 예술적 재구성이다. 1세기 베들레헴의 고고학적 복원을 검증한 모델은 아니다. 기존 이야기 텍스트는 변경하지 않았다.

## 성능 설계

반복 건축 디테일은 재질/지오메트리별 InstancedMesh로 묶는다. 올리브 수관과 풀도 인스턴스를 사용한다. 실시간 등불은 방문자 주변 4개(모바일 2개) + 탄생 장소 1개로 제한하고, 나머지는 발광 재질과 부드러운 바닥 표현을 쓴다. 그림자를 만드는 광원은 달빛 하나다.

모바일은 픽셀 비율 상한 1.25, 그림자 맵 512²; 데스크톱은 1.6, 1024². 풀과 천막은 GPU 정점 변형을 사용한다. 베들레헴 소스는 약 18KB이며 별도 모델/텍스처 다운로드는 없다. 프러스텀 컬링은 Three.js 기본 기능을 사용하며, 개별 건물 단위의 LOD/폐색 컬링은 아직 없다.

## 실제 브라우저 검증

Ego Chromium, localhost의 실제 WebGL 렌더링에서 검증했다. 측정값은 requestAnimationFrame 간격이며 GPU 단독 실행시간이 아니다. 브라우저/디스플레이 주사율·전원 상태의 영향을 포함한다.

| 조건 | 평균 프레임 간격 | p95 | 환산 평균 FPS |
|---|---:|---:|---:|
| 데스크톱 1540×1330, 탄생 장소, 240프레임 | 33.69ms | 34.40ms | 29.68 |
| 모바일 에뮬레이션 390×844, DPR 3 → 렌더 DPR 1.25, 180프레임 | 33.97ms | 49.40ms | 29.44 |

모바일은 동일 데스크톱 GPU의 화면·DPR·터치 에뮬레이션이다. 실제 Android/iPhone 성능 및 Safari 호환성은 아직 측정하지 않았다. 60fps 달성으로 보고하지 않는다.

검증 결과:

- 입구 → 탄생 장소 자동 이동 완료, 이야기 열기·닫기 후 탐험 복귀.
- 시장 도착 및 시야 확인. 처음 발견된 건물의 양 가림 문제를 카메라 높이/거리 보정과 시장 목적지 조정으로 수정.
- 모든 11개 월드가 로딩되며, 월드별 3개 이야기 목적지 총 33개 모두 경로 탐색 성공.
- 베들레헴 다섯 탐험 목적지 모두 시작점에서 경로 탐색 성공.
- 키보드 W 이동 확인. 전망대까지 실제 자동 이동 완료(도착 지형 높이 약 2.91). 전망대에서도 다섯 목적지와 세 이야기까지 경로 탐색 성공.
- 모바일 터치 바닥 지정 후 양 위치가 실제로 변경되고 도착함.
- 모바일 캔버스 487×1055, 픽셀 비율 1.25 적용 확인. 가로 넘침 없음.
- 11개 월드 순환 후 베들레헴의 지오메트리 84개·텍스처 6개로 복귀. 다른 월드에서는 베들레헴 텍스처가 해제되고 4개로 감소.
- 움직임 줄이기 에뮬레이션에서 reduced 설정 적용 확인. 모바일 가로 화면 844×390에서 가로 넘침 없고 하단 버튼이 화면 안에 표시됨. 마지막 로드의 Resource Timing에서 HTTP 400 이상 응답 없음.
- 구문 검사: `node --check journey/app.js`, `node --check journey/worlds/bethlehem.js` 통과.

진단은 `?qa=1`을 붙였을 때만 `window.journeyQA.state()`와 `.routes()`를 제공한다. 일반 방문에서는 노출하지 않는다.

## 다음 단계 전 권장 검수

이번 결과는 이전보다 탐험 공간과 재질·빛의 구성이 발전한 환경 초안이다. 여전히 건물 외곽의 각진 형태와 규칙적인 배치가 눈에 띈다. 영화적 완성도를 목표로 한다면 비대칭 외벽, 더 부드러운 모서리, 건물별 생활 흔적, 조명 전환의 부드러움을 추가로 다듬는 편이 좋다. 실제 휴대폰 1대 이상에서 성능 확인도 필요하다.

사용자 승인 이후에만 NPC 단계로 넘어간다. 주요 인물 단계에서는 별도의 아트 제작이 필요하다. GLB/glTF의 최종 캐릭터(스킨·리그·표정 포함), 마리아/요셉의 호흡·시선·손동작, 아기의 절제된 움직임을 연결해야 한다. 외부 무료 모델을 사용할 경우 상업적 이용·수정·웹 재배포 가능 여부와 출처 표시 조건을 개별 확인하고 라이선스를 보관해야 한다. 검증되지 않은 리소스는 현재 포함되어 있지 않다. 최종 모델은 불필요한 본·메시 제거, 텍스처 아틀라스, LOD 및 필요 시 KTX2/Meshopt 도입을 실제 크기·품질 측정 후 결정한다.
