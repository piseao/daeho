SO DO NOT FEAR CONTENT STUDIO GUIDE홈페이지

이야기를 직접 수정하고 발행하기

AI나 코드 편집 없이 관리자 화면에서 내용과 이미지를 바꿀 수 있습니다. 현재 사이트는 GitHub Pages에서 운영되므로 발행 권한은 GitHub 계정으로 확인합니다.

1. 편집하기

  1. 콘텐츠 관리에서 홈 화면, 이야기, 안내 페이지, 체험 소개, 사이트 설정 중 하나를 선택합니다.
  2. 입력란에서 문구를 바꾸세요. 이미지 선택으로 JPG·PNG·WebP 사진을 올리면 자동으로 크기를 줄입니다.
  3. 본문은 빈 줄로 문단을 나눕니다. 소제목은 ## 제목, 인용이나 고백은 > 내용으로 작성하세요.
  4. 미리보기에서 현재 편집 중인 페이지를 확인합니다. ‘모바일 너비’도 확인하세요.

2. 초안과 백업

‘초안 저장’은 이 브라우저에만 저장합니다. 다른 기기에서 작업하려면 ‘백업 받기’로 JSON 파일을 보관한 후 ‘백업 가져오기’로 옮기세요. 토큰은 백업에 포함되지 않습니다. 브라우저 저장 공간을 지우면 초안이 사라질 수 있습니다.

3. 처음 발행 권한 연결하기

  1. piseao/daeho 저장소에 쓰기 권한이 있는 GitHub 계정으로 Fine-grained personal access token 생성 화면을 엽니다.
  2. 이름은 ‘SDNF 홈페이지 편집’, 만료 기간을 설정합니다. Resource owner는 저장소 소유자, Repository access는 ‘Only select repositories’에서 daeho만 선택합니다.
  3. Repository permissions에서 Contents: Read and write를 허용합니다. Metadata 읽기 권한은 기본으로 포함됩니다. 계정이나 조직 정책에 따라 승인이 필요할 수 있습니다.
  4. 생성한 토큰을 관리자 ‘발행 계정 연결’의 비밀번호 입력란에 붙여 넣고 연결합니다. 채팅으로 토큰을 보내지 마세요.
  5. 토큰은 탭의 메모리에만 보관합니다. 연결을 끊거나 페이지를 새로고침하면 다시 연결해야 합니다. 토큰이 만료되면 GitHub에서 새로 발급하세요.

관리자 주소 자체는 공개되어 있습니다. 실제 사이트를 바꾸는 권한은 GitHub가 검사합니다. 별도 비밀번호를 HTML에 넣어 숨기는 방식이 아닙니다.

4. 발행하기

  1. ‘변경 내용 발행’을 누르고 공개될 글 수와 내려갈 글을 확인합니다.
  2. 내용과 이미지 사용 권한을 확인한 후 발행합니다.
  3. 내용·이미지·HTML 페이지가 한 번의 커밋으로 저장됩니다. GitHub Pages 반영까지 잠시 기다린 뒤 홈페이지를 새로고침하세요. 배포 상태 확인

다른 수정이 감지된 경우

관리자가 편집하는 사이 다른 사람이 발행하면 자동 덮어쓰기를 막습니다. 현재 초안을 백업하고 ‘최신 내용 불러오기’를 누른 뒤 필요한 변경을 다시 적용하세요. 최신 버전과 비교 없이 백업 전체를 덮어쓰지 않도록 주의해 주세요.

공개와 비공개

홈페이지에 발행하는 데이터는 공개 GitHub 저장소에 들어갑니다. 글의 ‘공개’ 체크를 해제하면 홈페이지의 목록과 글 페이지는 내려가지만 저장소와 커밋 이력에서 비밀이 되지는 않습니다. 개인정보나 비밀 문서는 입력하지 마세요. 아직 공개할 수 없는 원고는 로컬 초안으로만 보관하세요.

편집할 수 있는 범위

홈 대표 문구·이미지·고백, 글 작성·분류·순서·공개 상태, 소개·예배·배움·문의 페이지의 제목·본문·링크·영상, 홈 체험 소개, 사이트 이름과 소셜 주소를 관리합니다. 3D 게임의 맵·캐릭터·미션 코드는 이 편집기의 수정 대상이 아닙니다.

실수했을 때

발행 전에는 ‘최신 내용 불러오기’로 되돌릴 수 있습니다. 발행 후에는 이전에 받은 콘텐츠 백업을 검토해 다시 발행할 수 있습니다. GitHub에는 발행 이력이 남습니다. 이미지 삭제는 글에서 연결만 해제하며, 기존 이미지 파일은 이전 글의 복구를 위해 보존합니다.
