홈페이지가 갑자기 안 열릴 때 먼저 확인할 것들

주소·접속 환경·배포·도메인·HTTPS를 구분하고, 설정을 바꾸기 전에 증상을 기록하는 확인 순서입니다.

SO DO NOT FEAR · 2026-11-20 · 3분 읽기

홈페이지가 열리지 않으면 먼저 여러 설정을 바꾸고 싶어질 수 있습니다. 하지만 원인을 모른 채 도메인과 배포 설정을 한꺼번에 바꾸면 무엇이 문제였는지 더 알기 어려워집니다. 이 글의 목적은 모든 장애를 혼자 해결하게 하는 것이 아니라, 문제를 구분하고 필요한 도움을 정확히 요청하도록 돕는 것입니다.

1. 오류 문구와 영향을 기록합니다

정확한 주소, 발생 시각, 사용 기기와 브라우저를 적습니다. 전체 사이트가 안 되는지 특정 페이지만 안 되는지 확인합니다. 최근에 바꾼 파일이나 도메인 설정이 있는지도 기록합니다. 화면을 보관할 때 계정과 비공개 정보가 함께 찍히지 않도록 살핍니다.

2. 다른 접속 환경에서 비교합니다

주소의 철자와 경로를 확인하고 다른 브라우저나 기기, 허용되는 다른 네트워크에서 비교합니다. 한 환경에서만 생기는지 여러 환경에서 같은지 구분합니다. 무작정 모든 브라우저 데이터를 지우기보다 문제 범위를 먼저 확인합니다. 인증서 경고가 나오면 경고를 무시하고 로그인 정보를 입력하지 않습니다.

3. 배포와 주소 문제를 나눠 확인합니다

사용하는 호스팅의 상태 안내와 배포 결과를 확인합니다. GitHub Pages를 쓴다면 저장소의 Pages 설정과 최근 배포 상태를 살펴볼 수 있습니다. 사용자 지정 도메인과 기본 서비스 주소는 설정에 따라 리디렉션될 수 있어, 주소 하나가 열렸다는 사실만으로 모든 원인을 확정하지는 않습니다.

GitHub의 공식 안내는 사용자 지정 도메인 문제에서 CNAME, DNS와 HTTPS 등을 구분해 설명합니다. 실제 수정이 필요하다면 현재 설정을 보관하고 해당 서비스의 최신 안내를 따릅니다. 특히 메일에도 영향을 줄 수 있으므로 도메인의 DNS 기록을 통째로 삭제하거나 추측한 값으로 바꾸지 않습니다.

4. 한 가지 변경 후 결과를 확인합니다

원인과 수정안을 이해한 경우에만 변경하고 이전 값, 변경 시각과 결과를 남깁니다. 확실하지 않다면 기관 담당자나 지원자에게 증상을 먼저 보냅니다. 비밀번호를 보내는 대신 공식 초대와 필요한 접근 권한을 사용하는 편이 좋습니다.

첨부한 장애 확인표를 채우면 도움받는 시간이 줄어들 수 있습니다. 정상화 뒤에는 홈페이지 첫 화면뿐 아니라 예배 안내와 문의 링크, 새로 수정한 페이지도 확인합니다. 같은 장애가 반복되지 않도록 원인과 복구 방법을 기록하는 데까지가 운영의 한 과정입니다.
