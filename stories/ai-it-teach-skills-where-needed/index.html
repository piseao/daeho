기술이 필요한 곳에 기술을 전한다는 것

대신 만들어주는 일에서 한 걸음 더 나아가, 현장 담당자가 자신의 계정과 도구를 이해하고 직접 운영하도록 가르치는 방법입니다.

SO DO NOT FEAR · 2026-11-20 · 3분 읽기

도움을 요청받았을 때 기술을 아는 사람이 직접 처리하면 빠르게 끝날 수 있습니다. 하지만 그 사람이 떠난 뒤 작은 수정조차 하지 못한다면 현장의 어려움은 다시 돌아옵니다. 기술을 전한다는 것은 완성된 파일을 건네는 데서 멈추지 않고, 담당자가 이해하고 다시 해볼 수 있도록 옆에 시간을 내어주는 일입니다.

가르치는 사람이 많이 안다는 사실보다 배우는 사람이 지금 무엇을 해낼 수 있게 됐는지가 중요합니다. 강의가 끝났다는 확인과 배움이 남았다는 확인은 같지 않습니다. AI·IT 선교의 교육도 이 차이를 기억했으면 합니다.

요청받은 문제 하나에서 수업을 시작합니다

프로그램의 모든 메뉴를 설명하기보다 지금 반복되는 일을 묻습니다. 예배 시간을 바꾸기 어려운지, 주보 파일을 찾지 못하는지, 영상 자막을 올리는 과정에서 막히는지 살펴봅니다. 학습자의 기기, 인터넷 환경과 익숙한 도구도 함께 확인합니다. 가르치는 사람의 장비에서만 가능한 수업은 현장에서 이어지기 어렵습니다.

실습 목표는 확인할 수 있는 행동으로 적습니다. 예를 들어 “담당자가 예배 시간을 수정하고, 휴대전화에서 반영 여부를 확인한다”로 정할 수 있습니다. 이는 수업 설계 예시입니다. 기술 용어를 기억하는 시험보다 실제 필요한 작업을 해보는 편이 배움의 상태를 잘 드러냅니다.

보여주고, 함께 하고, 혼자 해보게 합니다

처음에는 작업을 한 번 보여주며 왜 그 순서인지 설명합니다. 두 번째에는 학습자가 직접 조작하고 옆에서 필요한 만큼 돕습니다. 마지막에는 안내 문서만 보고 다시 해보게 합니다. 시간이 더 걸리더라도 대신 클릭해버리지 않는 기다림이 필요합니다.

AI를 사용하는 실습이라면 정답처럼 보이는 결과를 받는 데서 끝내지 않습니다. 어떤 자료를 입력했는지, 빠진 조건은 없는지, 결과를 어떻게 확인했는지 학습자가 자기 말로 설명해보게 합니다. “왜 이렇게 했나요?”에 답하는 경험은 다음 문제를 만났을 때에도 도움이 됩니다.

계정과 기록은 현장에 남깁니다

교회와 선교단체가 자기 계정을 소유하고 접근 권한을 관리하도록 합니다. 개인 비밀번호를 교사에게 보내는 방식은 피하고, 필요한 경우 정식 초대와 권한 부여 기능을 사용합니다. 수업에는 공개 가능한 연습 자료를 사용하고 실제 교인 정보로 실습하지 않습니다.

마무리할 때 수정 순서, 실패했을 때 되돌리는 방법, 도움을 요청할 경로를 한 장으로 정리합니다. 녹화 자료를 만들 경우 참여자의 동의와 공개 범위를 확인합니다. 교육 뒤에는 일정한 점검 시간을 약속하되, 언제나 특정 한 사람에게만 의존해야 하는 구조는 줄여갑니다. 기술을 나누는 섬김은 상대가 스스로 해보는 기회를 넓힐 때 더 오래 남을 수 있습니다.
