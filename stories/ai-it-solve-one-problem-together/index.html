막힌 일을 AI와 함께 풀어가는 다섯 단계

도구부터 고르기보다 문제를 설명하고, 작은 실험과 검증을 반복해 실제 현장의 어려움을 줄이는 작업 순서를 안내합니다.

SO DO NOT FEAR · 2026-11-20 · 3분 읽기

“AI로 뭘 할 수 있나요?”라는 질문은 가능성을 여는 좋은 출발입니다. 그러나 현장의 일을 풀어갈 때에는 한 걸음 더 구체적인 질문이 필요합니다. “지금 누가 어떤 일을 반복해서 어렵게 하고 있나요?” AI를 잘 쓰는 출발점은 근사한 요청 문장을 외우는 것보다 해결할 문제를 정확히 바라보는 데 있습니다.

여기서는 공개 행사 안내를 정리하는 상황을 예시로 삼아 다섯 단계를 제안합니다. 특정 교회에서 실제로 시행한 성과 보고가 아니라, 자기 현장에 맞춰 바꿔볼 수 있는 작업 방법입니다.

1. 현재의 어려움과 원하는 결과를 나눕니다

“공지 업무가 힘들다” 대신 “같은 행사 정보를 홈페이지와 SNS에 다시 적다가 날짜가 다르게 올라간다”처럼 상황을 씁니다. 원하는 결과도 “AI 도입”이 아니라 “기준 원문 한 곳에서 안내를 준비하고 날짜를 일치시킨다”로 정합니다. 무엇이 해결되면 성공인지 먼저 합의합니다.

2. 필요한 자료와 제외할 자료를 정합니다

공개 가능한 행사명, 일정, 장소, 대상과 문의 방법만 모읍니다. 참가자 명단, 개인 연락처와 내부 메모는 입력 자료에서 뺍니다. 원문에 없는 내용을 만들지 말라는 조건을 적고, 정보가 빠졌을 때 표시할 방법도 정합니다. 서비스별 데이터 처리 조건은 실제 사용 전에 확인합니다.

3. 작은 결과 하나를 요청합니다

요청 예시: “다음 공개 행사 정보를 홈페이지 안내용 문장으로 정리해줘. 날짜와 장소는 그대로 유지하고, 없는 항목은 ‘확인 필요’로 남겨줘. 원문에 없는 약속이나 참여 혜택은 추가하지 마.” 먼저 한 채널의 초안만 만들고, 결과를 본 뒤 다음 작업을 요청합니다.

막혔다면 같은 요청을 무작정 반복하기보다 기대한 결과와 실제 결과의 차이를 설명합니다. 코드 문제라면 개인정보와 비밀값을 지운 오류 메시지, 재현 순서, 바뀌어도 되는 범위를 함께 알려줍니다. AI가 제안한 명령을 이해하지 못한 상태로 운영 서버에서 실행하지 않습니다.

4. 사람이 원문과 대조하고 실제로 확인합니다

일정과 장소를 항목별로 비교하고, 신청 링크가 열리는지 직접 확인합니다. 보기 좋은 문장을 사실 확인의 근거로 삼지 않습니다. Google의 생성형 AI 프로젝트 안내도 유창한 결과가 사실의 정확성을 보장하지 않으며 사람의 검증이 필요한 경우가 많다고 설명합니다. 처음에는 복사본과 테스트 환경에서 확인합니다.

5. 효과와 한계를 기록합니다

어떤 부분이 쉬워졌고 검토에는 얼마나 수고가 들었는지 돌아봅니다. 기대보다 복잡해졌다면 도입을 멈추거나 범위를 줄일 수 있습니다. 도움이 된 요청 방식과 점검표는 문서로 남겨 다음 담당자가 다시 사용할 수 있게 합니다. AI와 문제를 푼다는 것은 모든 판단을 맡기는 일이 아니라, 질문하고 확인하는 과정에 도구를 참여시키는 일입니다.
