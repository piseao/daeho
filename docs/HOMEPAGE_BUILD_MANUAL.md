# 개척교회와 소규모 공동체를 위한 홈페이지 제작 매뉴얼

이 문서는 So Do Not Fear 홈페이지의 제작 경험을 바탕으로, 개척교회·소규모 교회·선교단체·예배 공동체가 적은 비용으로 공개 정보형 홈페이지를 만들고 운영하는 방법을 설명한다.

## 1. 이 방식이 적합한 경우

다음과 같은 공개 정보를 전달하는 홈페이지에 적합하다.

- 교회 또는 공동체 소개
- 예배 시간과 장소
- 공지사항과 일정
- 설교 및 말씀 영상
- 기도제목 나눔 링크
- 사진 앨범 링크
- 칼럼과 신앙 콘텐츠
- 공식 문의 방법과 후원 안내

다음 기능이 필요하다면 GitHub Pages만으로는 부족하다.

- 회원가입과 로그인
- 교인 명부 또는 개인정보 관리
- 비공개 상담과 기도제목 저장
- 직접 결제와 후원 결제 처리
- 작성자가 자유롭게 글을 등록하는 커뮤니티 게시판

이 기능들은 별도 백엔드나 검증된 관리형 서비스를 이용해야 한다.

## 2. 시작 전에 결정할 내용

코드를 만들기 전에 다음 내용을 먼저 한 장으로 정리한다.

1. 공동체 이름과 한 문장 소개
2. 홈페이지를 방문했으면 하는 사람
3. 핵심 신앙고백과 사역 방향
4. 예배 시간과 장소
5. 공개할 연락 방법
6. 기도제목, 영상, 사진과 칼럼을 관리할 서비스
7. 홈페이지 운영 책임자와 보조 담당자
8. 사용할 도메인

정보가 확정되지 않았다면 임의로 만들어 공개하지 말고 `확정 후 안내`라고 표시한다.

## 3. 권장 운영 구조

```text
공식 홈페이지(GitHub Pages)
├── 공동체 소개와 예배 안내
├── 공개 공지사항
├── YouTube 말씀·예배 영상
├── Padlet 기도제목
├── Google 포토 앨범
└── Notion 칼럼(His Story)
```

홈페이지는 모든 서비스를 직접 구현하는 곳이 아니라 방문자가 필요한 공식 채널로 이동하는 출발점이다.

## 4. 필요한 계정과 준비물

- GitHub 계정
- 사용할 도메인과 DNS 관리 권한
- 공개 가능한 대표 이미지
- YouTube, Padlet, Google 포토 또는 Notion 계정
- Google Search Console 계정
- 네이버 서치어드바이저 계정

GitHub 계정에는 2단계 인증을 설정하고 복구 코드를 별도 장소에 보관한다.

## 5. 저장소 준비하기

### 새 저장소로 시작하는 경우

GitHub에서 공개 저장소를 만든 뒤 `index.html`, `styles.css`, `script.js`와 이미지 파일을 추가한다.

### 기존 저장소를 참고하는 경우

먼저 `LICENSE`를 확인한다. 라이선스가 없다면 공개되어 있어도 자유롭게 복제·수정·배포할 권한이 자동으로 주어지지 않는다.

재사용이 허용된 저장소라면 Fork하거나 clone한다.

```bash
git clone https://github.com/사용자명/저장소명.git
cd 저장소명
```

작업 전에는 항상 현재 상태를 확인한다.

```bash
git status
git pull origin main
```

## 6. 권장 파일 구조

```text
/
├── index.html                 # 홈페이지 구조와 검색 메타 태그
├── styles.css                # 디자인과 모바일 반응형 스타일
├── script.js                 # 공개 콘텐츠 표시
├── content/
│   └── site-data.json        # 공지와 카드형 콘텐츠 데이터
├── assets/                   # 이미지와 공개 파일
├── docs/
│   ├── PROJECT_VISION.md     # 프로젝트 취지와 신앙·운영 방향
│   ├── HOMEPAGE_BUILD_MANUAL.md
│   ├── SITE_OPERATIONS.md    # 실제 사이트 운영 기준
│   └── SEARCH_REGISTRATION.md
├── robots.txt
├── sitemap.xml
├── CNAME                     # 사용자 도메인
└── README.md                 # 저장소의 첫 안내
```

## 7. 홈페이지 내용 바꾸기

### 반드시 교체할 항목

- 교회 또는 공동체 이름
- 한 문장 소개
- 대표 이미지와 이미지 대체 설명
- 예배 시간과 장소
- 기도제목 및 영상 링크
- 공지사항
- 문의 방법
- 도메인과 검색 메타 정보

다른 교회의 실제 시간, 장소, 연락처와 후원 계좌를 그대로 남기지 않는다.

### 콘텐츠 작성 기준

- 방문자가 사용하는 쉬운 언어로 작성한다.
- 확정된 정보와 계획을 명확히 구분한다.
- 한 화면에 너무 많은 내용을 넣지 않는다.
- 모바일 화면에서 먼저 읽어 본다.
- 신학적 주장은 성경 문맥을 확인하고 검토자를 둔다.
- 사진 속 인물, 특히 아동의 공개 동의를 확인한다.

## 8. 외부 서비스 연결하기

### YouTube

영상의 공유 주소에서 영상 ID를 확인하고 개인정보 보호 강화 주소를 사용한다.

```html
<iframe
  src="https://www.youtube-nocookie.com/embed/영상ID"
  title="영상 제목"
  allowfullscreen
></iframe>
```

영상은 16:9 비율을 유지하고 모바일에서 가로폭이 넘치지 않게 한다.

### Padlet

공개 방문 링크만 연결한다. 관리자 링크나 편집 전용 링크는 저장소에 넣지 않는다. 민감한 기도제목과 개인정보를 공개하지 않도록 안내하고 승인·삭제 담당자를 정한다.

### Google 포토

공유 앨범 링크를 사용한다. 링크를 받은 사람이 다시 공유할 수 있으므로 공개 동의를 받은 사진만 올린다.

### Notion 칼럼

노션 페이지 오른쪽 위 `공유`에서 `게시`를 선택하고 공개된 `notion.site` 주소를 홈페이지에 연결한다. 방문자는 공개 페이지를 회원가입 없이 읽을 수 있다.

노션 페이지는 홈페이지 안에 iframe으로 넣기보다 새 창 링크로 연결한다. 검색 노출이 중요하다면 다음 단계로 발전시킨다.

```text
노션에서 글 작성
→ Notion API로 공개 글 가져오기
→ 홈페이지 도메인 아래 정적 HTML 생성
→ GitHub Pages 자동 배포
```

API 비밀키는 HTML이나 공개 저장소에 넣지 않고 GitHub Secrets에 저장한다. 자세한 공개 설정은 [Notion Sites 공식 안내](https://www.notion.com/ko/help/public-pages-and-web-publishing)를 참고한다.

## 9. 로컬에서 확인하기

파일을 직접 더블클릭하는 것보다 간단한 로컬 서버로 확인하는 것이 정확하다.

```bash
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 연다. 확인이 끝나면 터미널에서 `Ctrl+C`로 종료한다.

### 화면 확인 항목

- 데스크톱과 모바일에서 글자가 겹치지 않는가
- 상단 메뉴가 줄바꿈되어도 읽을 수 있는가
- 이미지가 찌그러지지 않는가
- YouTube 영상의 가로·세로 비율이 맞는가
- 모든 외부 링크가 올바른 공개 주소로 열리는가
- 확정되지 않은 예배 정보가 사실처럼 표시되지 않았는가

## 10. GitHub Pages 배포하기

1. GitHub 저장소의 `Settings`로 이동한다.
2. `Pages`를 선택한다.
3. 배포 방식을 `Deploy from a branch`로 선택한다.
4. 브랜치를 `main`, 폴더를 `/ (root)`로 선택한다.
5. 저장하고 배포 주소가 생성될 때까지 기다린다.

변경 내용을 배포할 때:

```bash
git add .
git commit -m "Update worship information"
git push origin main
```

푸시가 성공한 것과 Pages 배포가 성공한 것은 다르다. 저장소의 Pages 또는 Actions 화면에서 배포 완료를 확인한 뒤 실제 홈페이지를 다시 연다. 자세한 설정은 [GitHub Pages 공식 문서](https://docs.github.com/pages/getting-started-with-github-pages/creating-a-github-pages-site)를 참고한다.

## 11. 사용자 도메인 연결하기

예를 들어 `examplechurch.org`를 연결한다면 저장소의 `CNAME` 파일에는 도메인 한 줄만 작성한다.

```text
examplechurch.org
```

도메인 업체의 DNS 관리 화면에서 루트 도메인 A 레코드를 GitHub Pages 주소로 연결한다.

```text
@  A  185.199.108.153
@  A  185.199.109.153
@  A  185.199.110.153
@  A  185.199.111.153
```

`www`는 GitHub 사용자 페이지 주소로 연결한다.

```text
www  CNAME  사용자명.github.io
```

DNS 업체에 따라 `@` 대신 `루트 도메인`을 선택하고 A 레코드를 여러 개 추가하는 방식이 다를 수 있다. 적용에는 시간이 걸릴 수 있다. GitHub 설정에서 도메인 확인 후 `Enforce HTTPS`를 켠다.

DNS 값은 변경될 수 있으므로 적용 전에 [GitHub 사용자 도메인 공식 문서](https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)를 다시 확인한다.

## 12. 기본 검색 최적화

검색 최적화는 키워드를 반복해서 넣는 일이 아니다. 페이지마다 누구를 위한 어떤 정보인지 제목과 본문에 분명하게 작성하는 것이 먼저다.

### 기본 메타 태그

```html
<title>교회 이름 | 지역과 핵심 소개</title>
<meta name="description" content="교회 소개, 예배 시간과 제공하는 정보를 자연스럽게 설명합니다.">
<meta name="robots" content="index, follow">
<link rel="canonical" href="https://공식도메인/">
```

### 함께 준비할 파일

- `robots.txt`: 검색 로봇의 수집 허용 범위와 사이트맵 위치
- `sitemap.xml`: 검색에 등록할 공식 페이지 목록
- Open Graph: 카카오톡과 SNS에 공유될 제목·설명·이미지
- 구조화 데이터: Organization, WebSite, WebPage와 Article 정보

검색 인증 코드는 각 사이트에서 새로 발급받아 `<head>`에 넣는다. 다른 홈페이지의 인증 코드를 복사하지 않는다.

### 검색 서비스 등록

1. Google Search Console에 공식 도메인을 등록한다.
2. 네이버 서치어드바이저에 공식 도메인을 등록한다.
3. HTML 메타 태그 방식으로 소유권을 확인한다.
4. 두 서비스에 `sitemap.xml`을 제출한다.
5. 색인은 즉시 보장되지 않으므로 기다리며 실제 검색 결과를 확인한다.

## 13. 칼럼과 검색 노출

글을 노션에만 공개하면 검색 가치가 `notion.site`에 쌓일 수 있다. 홈페이지 검색 노출을 키우려면 공식 도메인 안에 최소한 다음 내용을 둔다.

- 칼럼 제목
- 2~3문장의 고유한 요약
- 주제 분류와 태그
- 작성일
- 원문 링크

가장 좋은 방식은 노션을 비공개 작성 도구로 사용하고 최종 글을 공식 홈페이지의 고유 주소로 생성하는 것이다.

```text
https://examplechurch.org/his-story/article-title.html
```

각 글에는 고유한 title, description, canonical과 Article 구조화 데이터를 설정한다. 같은 글을 여러 주소에 그대로 복제하지 않는다.

## 14. Issue와 Pull Request 활용하기

### Issue를 만드는 경우

- 변경할 내용이 아직 작업되지 않았을 때
- 여러 사람이 요청과 진행 상황을 확인해야 할 때
- 버그, 개선안과 콘텐츠 요청을 기록할 때

Issue 예시:

```text
제목: 주일 예배 장소 변경

- 변경 전: 기존 장소
- 변경 후: 새 장소
- 적용일: 2026-00-00
- 확인 담당자: 담당 역할
```

### 바로 수정해도 되는 경우

- 혼자 운영하며 변경 내용이 작고 확정되어 있을 때
- 최신 코드를 받은 뒤 충돌 없이 수정할 수 있을 때

여러 사람이 작업한다면 별도 브랜치와 Pull Request를 사용해 검토한 뒤 `main`에 합친다.

## 15. AI에게 홈페이지 작업 요청하기

AI에게는 저장소, 지켜야 할 문서, 원하는 결과와 검증 범위를 함께 알려준다.

```text
https://github.com/사용자명/저장소명 저장소를 확인해줘.
먼저 docs/PROJECT_VISION.md, docs/SITE_OPERATIONS.md,
docs/HOMEPAGE_BUILD_MANUAL.md를 읽고 기존 디자인을 유지해줘.

요청 작업:
- 상단 메뉴에 새 링크 추가
- 모바일과 데스크톱 화면 확인
- 외부 링크와 검색 메타 태그 검사
- 변경 내용을 설명하고 승인된 경우에만 main에 push
```

외부 코드를 가져올 때는 다음과 같이 요청한다.

```text
실행하거나 복사하기 전에 라이선스, 의존성, 설치 스크립트와
비밀정보 포함 여부를 검사해줘. 관리자 권한이나 삭제 작업은
먼저 설명하고 승인 없이 실행하지 마.
```

AI가 만든 문구, 신학적 글, 실제 예배 정보, 사진 공개 범위와 후원 정보는 운영자가 최종 확인해야 한다.

## 16. 공개 저장소 보안

### 공개해도 되는 정보

- 홈페이지 코드와 공개 디자인
- 확정된 예배 시간과 장소
- 공개 공지
- 공개 영상과 앨범 링크
- 검색 사이트 인증 메타 태그

### 공개하면 안 되는 정보

- 비밀번호
- API 비밀키와 관리자 토큰
- OAuth Client Secret
- 서비스 계정 JSON
- 비공개 기도제목과 상담 내용
- 교인·후원자 명단과 개인정보
- 관리자 또는 편집 전용 링크

비밀정보를 한 번 커밋하면 현재 파일에서 삭제해도 Git 기록과 다른 사람의 clone에 남을 수 있다. 노출되었다면 먼저 해당 키를 폐기하고 재발급한다.

## 17. 저작권과 라이선스

- 공개 저장소와 오픈소스는 같은 뜻이 아니다.
- 저장소의 `LICENSE`가 코드 재사용 범위를 결정한다.
- 이미지와 영상은 촬영자와 등장 인물의 권리를 확인한다.
- 폰트의 웹 사용과 재배포 조건을 확인한다.
- 설교 영상과 글은 원저작자의 공개 및 인용 범위를 확인한다.
- 성경 번역문을 길게 인용할 때는 해당 번역본의 저작권 정책을 확인한다.

다른 교회가 이 프로젝트를 재사용하도록 허용하려면 소유자가 MIT, Apache-2.0 등 적절한 코드 라이선스를 검토해 선택해야 한다. 신앙 콘텐츠와 사진에는 코드와 다른 조건을 둘 수 있다.

## 18. 정기 운영 일정

### 공지나 예배 정보 변경 시

1. 정보가 최종 확정되었는지 확인한다.
2. 최신 코드를 pull한다.
3. 필요한 파일만 수정한다.
4. 모바일과 데스크톱에서 확인한다.
5. commit과 push를 진행한다.
6. Pages 배포 완료 후 공식 도메인에서 확인한다.

### 월 1회

- 예배 시간과 장소 확인
- 깨진 외부 링크 확인
- 오래된 공지 정리
- 담당자와 계정 권한 확인
- 검색도구의 색인 오류 확인

### 연 1회

- 도메인 갱신과 결제 담당자 확인
- GitHub 및 외부 서비스 복구 수단 확인
- 개인정보와 사진 공개 범위 재검토
- 운영문서와 실제 운영 방식 비교

## 19. 자주 발생하는 문제

### push했는데 홈페이지가 바뀌지 않는다

- Pages 배포가 완료되었는지 확인한다.
- 공식 도메인과 기본 GitHub Pages 주소를 혼동하지 않았는지 확인한다.
- 브라우저 강력 새로고침 또는 다른 브라우저로 확인한다.

### 도메인이 연결되지 않는다

- `CNAME` 파일의 도메인이 정확한지 확인한다.
- DNS에 이전 A 또는 CNAME 레코드가 남아 충돌하는지 확인한다.
- DNS 전파를 기다린다.
- GitHub Pages 설정의 사용자 도메인 상태를 확인한다.

### HTTPS가 활성화되지 않는다

- DNS 연결이 먼저 올바르게 완료되어야 한다.
- 인증서 발급에는 시간이 걸릴 수 있다.
- GitHub Pages에서 도메인 확인 후 `Enforce HTTPS`를 선택한다.

### 외부 링크가 로그인 화면을 보여준다

- 작업용 주소가 아닌 공개 공유 주소인지 확인한다.
- Notion은 `app.notion.com` 작업 주소가 아니라 게시된 `notion.site` 주소를 사용한다.
- Padlet과 Google 포토도 비공개 또는 관리자 링크가 아닌지 확인한다.

## 20. 공개 전 최종 체크리스트

- [ ] 공동체 이름과 소개가 정확하다.
- [ ] 예배 시간과 장소가 확정된 정보다.
- [ ] 모바일과 데스크톱 화면이 정상이다.
- [ ] 기도제목, 영상, 사진과 칼럼 링크가 공개 주소로 열린다.
- [ ] 개인정보와 비밀키가 저장소에 없다.
- [ ] 사진과 콘텐츠의 공개·사용 권한을 확인했다.
- [ ] 공식 도메인과 HTTPS가 정상이다.
- [ ] title, description, canonical이 올바르다.
- [ ] robots.txt와 sitemap.xml이 열린다.
- [ ] Google과 네이버 소유권 확인 및 사이트맵 제출을 완료했다.
- [ ] 운영 담당자와 계정 복구 방법이 정리되어 있다.
- [ ] GitHub Pages 배포 후 실제 주소에서 최종 확인했다.

## 마무리

처음부터 모든 기능을 만들 필요는 없다. 정확한 예배 정보, 공동체의 신앙과 방향, 안전한 연락 통로를 먼저 제공하고 실제 필요가 생길 때 기능을 추가한다.

작고 단순한 홈페이지라도 꾸준히 관리되고 신뢰할 수 있다면, 복음을 알아가고 교회를 찾는 사람에게 귀한 첫 연결점이 될 수 있다.
