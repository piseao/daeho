# AI·IT 선교 지원 실행 계획

## 비전

> 강의와 세팅으로 교회와 선교단체의 기술 장벽을 낮추고, AI와 IT를 복음을 전하고 공동체를 세우는 선교의 도구로 사용한다.

So Do Not Fear의 중심은 개혁주의 복음을 노래하는 예배팀이다. 홈페이지 제작 교육과 AI·IT 지원은 이 정체성에서 흘러나오는 섬김이며, 기술 자체를 자랑하거나 교회와 선교 현장의 주도권을 대신하는 일이 아니다.

우리는 작고 연약해도 복음을 위해 필요한 것을 함께 만들 수 있다고 믿는다. AI와 바이브 코딩을 배우는 그리스도인이 늘어나고, 각자의 작은 기술과 경험이 연결되어 교회와 선교 현장을 실제로 돕는 사역팀으로 성장하는 것을 장기 비전으로 삼는다.

## 사명의 세 축

### 1. 예배팀을 세운다

- 5솔라와 튤립으로 요약되는 개혁주의 복음을 분명히 고백한다.
- 예수 그리스도의 생명이 우리를 살리셨음을 예배와 콘텐츠로 전한다.
- 두렵고 떨리는 삶 속에서도 하나님이 함께하시기에 두렵지 않음을 노래한다.
- YouTube, Instagram과 카카오톡 모임을 통해 예배, 말씀, 기도와 관계를 이어간다.

### 2. 강의와 세팅으로 공동체를 돕는다

- YouTube 본 강의와 Shorts, GitHub 문서를 무료로 공개한다.
- 영상을 따라 직접 만들 수 있는 사람에게 템플릿과 점검표를 제공한다.
- 개인적인 도움이 필요한 담당자에게 1:1 또는 원격 유료 강의를 제공한다.
- 홈페이지를 대신 소유하지 않고 해당 공동체 담당자가 직접 수정·배포하도록 교육한다.
- 지원 과정에서 반복되는 문제와 해결법을 익명화해 공개 문서에 다시 반영한다.

### 3. AI·IT로 선교 현장을 지원한다

- 교회·선교단체 공개 홈페이지 제작과 개선
- 다국어 홈페이지와 안내문 번역 초안
- 설교·사역 영상의 자막 초안과 짧은 영상 재구성
- 공지, 뉴스레터, 교육 자료와 운영 문서의 초안
- 검색 등록, 접근성, 모바일 화면과 기본 보안 점검
- 반복 행정 업무를 줄이는 안전한 자동화 안내
- 현지 담당자가 이어서 운영할 수 있는 교육과 인수인계

## 지원 원칙

1. **복음 중심:** 기술보다 복음, 예배와 사람을 먼저 둔다.
2. **현장 주도:** 교회와 선교단체가 계정, 콘텐츠와 최종 결정을 소유한다.
3. **교육 우선:** 가능하면 대신 처리하는 데서 끝내지 않고 운영 방법을 가르친다.
4. **무료 경로 유지:** 공개 강의와 문서만으로도 기본 홈페이지를 완성할 수 있게 한다.
5. **비용 투명성:** 무료 서비스, 외부 비용과 강의·세팅 비용을 구분하여 사전에 알린다.
6. **개인정보 최소화:** 교인 명부, 상담, 비공개 기도제목과 계정 비밀정보를 수집하지 않는다.
7. **사람의 최종 검토:** AI 결과는 초안으로 취급하며 사실, 번역과 신학 내용을 사람이 확인한다.
8. **지속 가능성:** 담당자, 복구 방법과 운영 절차를 문서로 남긴다.

## 지원 단계

```text
무료 콘텐츠 발견
→ 영상·문서로 직접 실습
→ 공개 질문과 카카오톡 학습 모임
→ 개인 지원 요청
→ 사전 진단과 지원 범위 결정
→ 무료·감면 또는 유료 지원 구분
→ 1:1 강의·원격 세팅
→ 운영자 교육과 인수인계
→ 익명화한 해결 기록을 공개 자료로 환원
```

## 무료·유료·선교 지원 구분

| 구분 | 제공 대상 | 내용 | 운영 기준 |
| --- | --- | --- | --- |
| 무료 공개 지원 | 누구나 | 영상, Shorts, 코드, 템플릿, 매뉴얼 | 회원가입이나 결제 없이 기본 자료 공개 |
| 공개 커뮤니티 지원 | 학습자·운영자 | GitHub Issue와 카카오톡 공통 질문 | 개인정보와 계정 정보는 받지 않음 |
| 유료 개인 지원 | 맞춤 도움이 필요한 공동체 | 1:1 강의, 원격 진단, 제작 동행 | 범위·시간·비용·환불 기준 사전 합의 |
| 무료·감면 선교 지원 | 기술·재정 여건이 부족한 현장 | 긴급 세팅, 교육, 기본 홈페이지 | 필요성·공익성·운영 담당자 유무를 검토 |

유료 활동으로 생긴 수익의 사용 원칙과 선교 지원 비율은 운영이 시작되기 전에 별도 기준으로 정하고 공개 범위를 결정한다. 무료·감면 지원은 호의만으로 선정하지 않고 목적, 실제 필요, 담당자, 유지 가능성과 개인정보 위험을 함께 검토한다.

## AI 활용 가능 범위

### 활용하기 좋은 일

- 공개 홈페이지의 구조와 문구 초안
- 공개된 원문을 바탕으로 한 번역과 자막 초안
- 반복되는 공지와 교육 문서의 형식 정리
- 접근성, 링크, 맞춤법과 코드 오류 점검
- 공개 콘텐츠를 여러 SNS 형식으로 재구성

### 맡기지 않거나 반드시 사람이 검토할 일

- 설교, 신앙고백과 교리의 최종 판단
- 목회 상담과 비공개 기도제목 처리
- 교인, 아동, 후원자와 선교지 민감정보 분석
- 계정 비밀번호, 복구 코드와 API 비밀키 처리
- 법률, 세무, 재정과 안전에 관한 최종 결정
- 박해 위험 지역의 위치, 이름과 활동 정보 공개

## 12개월 실행 로드맵

### 1단계 · 기반 정리 (1개월)

- 홈페이지에 예배팀 정체성, 신앙고백과 두려움에 관한 핵심 메시지 반영
- YouTube 강의안과 Shorts 대본 확정
- 일반 문의와 개인 강의 요청 항목을 Google Forms에 구분
- 무료·유료 지원 범위, 개인정보와 원격 지원 기준 작성
- 시연용 계정과 개인정보 없는 예제 자료 준비

### 2단계 · 무료 강의 시작 (2~3개월)

- `공짜 홈페이지?` 0강과 기획·배포 핵심 강의 우선 공개
- 주 1회 본 강의, 주 2회 Shorts 시험 운영
- GitHub 제작 매뉴얼과 영상 설명란 상호 연결
- 2~3개 공동체가 영상을 보고 직접 완성하도록 파일럿 진행
- 반복 질문과 이탈 구간을 기록해 강의 수정

### 초기 수요 검증 기준

처음부터 큰 유료 서비스로 시작하지 않고 4~6주 동안 작은 파일럿으로 확인한다.

1. 목회자·선교사·홈페이지 담당자 10명에게 현재 가장 어려운 점을 인터뷰한다.
2. 무료 온라인 설명회 또는 0강을 공개하고 문의 유형을 기록한다.
3. 3개 공동체가 무료 자료로 직접 홈페이지를 만들어 보게 한다.
4. 그중 개인 지원을 원하는 사람에게 1:1 기초 강의와 원격 문제 해결을 각각 시험한다.
5. 상담 요청 수, 실제 결제 의향, 완료율과 스스로 운영할 수 있는지를 확인한다.

수요가 있다고 판단할 최소 신호:

- 4~6주 안에 구체적인 지원 문의 10건 이상
- 범위와 비용을 안내한 뒤 유료 진행 의사 3건 이상
- 무료 자료만으로 홈페이지를 완성한 사례 2곳 이상
- 같은 문제가 세 번 이상 반복되어 표준 강의나 템플릿으로 만들 수 있음

수치가 나오지 않으면 수요가 없다고 단정하기보다 대상, 메시지와 제공 범위를 좁혀 다시 검증한다. `무료 홈페이지`보다 `담당자가 직접 운영하도록 옆에서 가르쳐 주는 교회 맞춤 세팅`에 반응이 있는지 별도로 확인한다.

### 3단계 · 커뮤니티와 개인 지원 (4~6개월)

- 카카오톡 모임 운영 원칙, 관리자와 공지 형식 확정
- 공개 질문은 GitHub Issue와 매뉴얼에 축적
- 1:1·원격 유료 강의의 신청, 사전 진단과 인수인계 절차 시험
- 무료·감면 선교 지원 대상 1~2곳을 선정해 실제 사례 축적
- 사례 공개 전 공동체 이름, 사진과 활동 정보의 공개 동의 확인

### 4단계 · AI·IT 선교 지원 확장 (7~9개월)

- 다국어 안내, 자막과 운영 문서 지원 파일럿
- 교회·선교단체 유형별 홈페이지 템플릿 분리
- 개인정보를 제거한 문제 해결 사례와 체크리스트 공개
- 신학, 번역, 보안과 현장 상황을 검토할 협력자 연결
- 지원 요청이 감당 가능한 범위를 넘지 않는지 월별 점검

### 5단계 · 지속 가능한 운영 (10~12개월)

- 무료·유료·감면 지원 결과와 비용 구조 검토
- 수익 중 선교 지원에 사용할 기준과 회계 기록 방식 확정
- 강의, 템플릿과 외부 서비스 변경 사항 정기 업데이트
- 협력 교회·선교단체와 다음 해 지원 우선순위 결정
- 한 사람에게 집중된 계정과 지식을 공동 운영 체계로 전환

## 정기 운영 리듬

### 매주

- 예배 또는 말씀 콘텐츠 1건
- 홈페이지 제작 본 강의 또는 Shorts 1~3건
- 문의와 공개 질문 확인

### 매월

- 홈페이지 외부 링크, 폼과 배포 상태 점검
- 제작 매뉴얼과 자주 묻는 질문 업데이트
- 지원 요청, 완료 사례와 감당 가능한 작업량 검토
- 개인정보나 계정 정보가 공개 채널에 남지 않았는지 확인

### 분기마다

- 예배팀 사명과 AI·IT 지원이 서로 충돌하거나 한쪽을 압도하지 않는지 검토
- 무료 강의로 실제 홈페이지를 완성한 공동체 수 확인
- 유료 강의의 범위·비용·만족도와 선교 지원 여력 점검
- 외부 서비스 정책, 보안 기준과 강의 화면을 최신 상태로 수정

## 성과 지표

조회수와 팔로워 수보다 실제 공동체가 안전하게 사역을 이어가는지를 우선한다.

- 무료 강의로 홈페이지를 완성한 공동체 수
- 3개월 이상 스스로 수정·운영한 공동체 수
- 운영 담당자와 보조 담당자가 함께 준비된 비율
- 무료·감면 지원을 받은 선교 현장과 완료율
- AI 활용 후 절감된 반복 작업 시간
- 공개 문서로 환원된 해결 사례 수
- 개인정보·보안 사고 건수
- 예배와 지역 교회 공동체로 연결된 실제 사례

## 지원 요청 검토 질문

1. 이 요청은 복음 사역과 공동체의 실제 필요를 돕는가?
2. 공개 홈페이지와 AI가 적합한 문제인가?
3. 개인정보, 현지 안전과 계정 위험은 없는가?
4. 해당 공동체의 최종 책임자와 운영 담당자가 있는가?
5. 무료 자료만으로 해결할 수 있는가, 개인 지원이 필요한가?
6. 무료·감면과 유료 중 어떤 방식이 공정하고 지속 가능한가?
7. 지원 후 담당자가 스스로 운영할 수 있는가?
8. 배운 내용을 다른 공동체를 위한 자료로 안전하게 환원할 수 있는가?

## 꾸준히 업데이트하는 방법

- 이 문서를 비전과 연간 계획의 기준 문서로 사용한다.
- GitHub 사이트 방향성 이슈에 단계별 체크리스트, 결정과 다음 행동을 기록한다.
- 완료된 작업은 날짜와 결과 링크를 이슈 댓글로 남긴다.
- 새 아이디어는 바로 홈페이지에 넣지 않고 비전 적합성, 안전과 운영 부담을 먼저 검토한다.
- 매월 마지막 주에 이 문서와 YouTube 강의안을 함께 검토한다.
