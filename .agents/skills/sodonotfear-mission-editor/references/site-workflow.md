# sodonotfear.com 원본과 게시 절차

## 저장소와 작업 위치

- 공식 사이트: https://sodonotfear.com/
- 원격 저장소: https://github.com/piseao/daeho
- 공개 기준 브랜치: `main`
- 알려진 로컬 작업 폴더: `/Users/onmam008/daeho`

먼저 실제 checkout의 `AGENTS.md`, 운영 지침, `git status`, 원격과 브랜치 차이를 확인한다. 알려진 로컬 폴더에는 사용자 작업과 분기된 이력이 남아 있을 수 있다. 오래된 로컬 데이터를 최신 main에 통째로 올리지 않는다. 최신 원격 기준 별도 clone/작업 사본에서 요청한 변경만 통합하는 방식이 유용하다. 이전 세션의 `/tmp` 사본이 여전히 존재하거나 최신이라고 가정하지 않는다.

사용자가 관리자에서 직접 게시한 최신 글도 보존한다. 배포 직전 원격 변경을 확인하고 충돌하면 내용 단위로 다시 통합·검증한다. 로컬 작업의 강제 초기화·무차별 stash/삭제·강제 push를 하지 않는다. 웹사이트 게시 요청은 해당 콘텐츠의 커밋·배포를 포함하지만, 관련 없는 변경·다른 서비스의 메시지 전송·새 유료 서비스 설정까지 허용하는 것은 아니다.

## 콘텐츠 구조: 실제 코드를 확인한 뒤 사용

2026-11-20 확인 구조이며 현재 코드가 달라지면 현재 구현을 우선한다.

- `content/editorial.json`: 설정·카테고리·글·안내 페이지·프로젝트의 콘텐츠 원본.
- `editorial/render.mjs`: 유효성 검사, 글/아카이브/사이트맵, 공통 HTML 생성.
- `editorial/catalog.mjs`: `getCategories`, `columnPosts`, 분류 관리. `columnPosts`는 공개된 칼럼을 선택한다.
- `editorial/magazine-home.mjs`: 메인 추천과 최신 칼럼.
- `editorial/finalize.mjs`: 기관·페이지·탐색경로 등의 JSON-LD와 검색 메타데이터.
- `editorial/digital-mission.mjs`: 디지털 선교 대표 가이드.
- `editorial/assets.mjs`: 공통 CSS/JS 버전. 스타일·스크립트를 바꿨을 때 갱신한다.
- `tools/build-editorial.mjs`: `buildFiles`로 정적 HTML과 사이트맵 생성.
- `admin/admin.mjs`, `admin/publisher.mjs`: 관리자 편집·GitHub 발행. 원격 base commit을 확인하고 최신 tree를 기반으로 발행해 기존 자산을 보존한다.

**생성 HTML만 수정하지 않는다.** 다음 관리자 발행에서도 유지되도록 원본 JSON·필요한 생성 코드를 반영하고 빌드한다. 원본 외의 기존 필드를 임의로 없애지 않는다. 기존 4개 안내 페이지와 walk/journey 등의 별도 기능은 이 작업 때문에 바꾸지 않는다.

## 글 필드와 본문 형식

기본 글 필드:
`slug`, `title`, `summary`, `category`, `body`, `date`, `author`, `published`, `featured`, `image`, `alt`, `link`, `linkLabel`.

추가 지원 필드:
- `dateModified`: 실제 수정일. 최초 `date`는 유지.
- `relatedLinks`: `{label, url}` 목록. 출처·다음 글·빈 양식과 문의 연결.
- `photoCredit`: `{photographer, url, license, verifiedOn}`. 현재 화면은 사진가·사진 원본·Unsplash 라이선스를 표시한다.

`slug`는 중복 없는 영문 소문자·숫자·하이픈이다. 발행 후 기존 slug를 바꾸지 않는다. `category`는 현재 목록에 있는 정확한 명칭을 사용한다. 이미 `categories`가 있으면 그대로 확장한다. 없다면 `getCategories(d)`의 현재 목록을 바탕으로 추가한다. 청년 설교에는 중복 없이 `청년 설교`를 한 번만 추가한다. 목록 전체를 하드코딩해 교체하지 않는다.

현재 `prose()`는 빈 줄의 문단 구분, `## 소제목`, `> 인용/기도문`을 처리한다. 일반 Markdown 링크·표·HTML을 자동으로 렌더링한다고 가정하지 않는다. 링크는 지원되는 `relatedLinks`와 하단 `link`를 사용하고, 길고 복잡한 표는 읽기 쉬운 빈 양식 파일로 제공한다.

작성 명의는 기존에 쓰는 `SO DO NOT FEAR`를 기본으로 하되 사용자 지정을 우선한다. 청년 설교의 AI 도움/초안 표시는 반드시 **본문**에도 쓴다.

## 사진과 빈 양식의 지속성

일반 라이선스로 직접 확인해 내려받은 사진은 적절한 `assets/editorial/<묶음>/` 경로에 보관하고 파일과 함께 출처 manifest를 남길 수 있다. 기존 파일을 재사용할 경우 연결된 다른 글도 고려해 덮어쓰지 않는다. Unsplash API 이용 시에는 이 저장 관행을 그대로 적용하지 말고 최신 API의 핫링크·다운로드 이벤트 규칙과 화면 출처 요구를 따른다.

빈 양식은 `assets/resources/<묶음>/`에 실제 텍스트 등으로 만들고 글에서 연결한다. 내용을 복사하거나 저장할 방법을 안내하고 파일 응답도 확인한다. 불필요한 개인정보 입력 양식이나 수집 기능을 새로 만들지 않는다. 기존 자산은 추후 관리자 게시 때에도 남아야 한다.

## 메인 노출의 중요한 조건

- 공개 칼럼은 `published: true`로 칼럼 목록과 해당 카테고리 필터에 들어간다.
- 현재 추천 칼럼은 `featured: true`인 대상 글 중 **목록 순서 앞에서 최대 8편**이다. 새 글을 메인 추천에 넣으려면 그 규칙을 충족시킨다. 글 수가 8편을 넘으면 전체가 카드에 동시에 보인다고 보고하지 않는다.
- 최신 칼럼은 **추천 여부와 관계없이 날짜순 최대 10편**이다. 같은 날짜의 글은 입력 순서도 확인한다. 기존 관리자 순서 조정 기능을 임의로 없애지 않는다.
- 새 묶음을 앞에 추가할 수 있지만 기존 글의 상대 순서와 공개 여부·내용은 보존한다. 추천에서 밀려난 글도 칼럼과 카테고리에서 계속 읽을 수 있어야 한다.
- 사진이 있는 새 글은 메인 카드에도 실제 사진이 나오는지 확인한다. 현재 추천 카드의 사진 표시는 `image`와 `photoCredit`의 존재에 연결되어 있다.
- 관리자에서 다음 글을 발행해도 본문·사진·출처·자료와 분류가 유지되는지 생성·발행 구조를 확인한다.

## 검증과 배포

프로젝트의 현재 도구를 먼저 확인한다. 알려진 빌드/검증 명령:

```sh
node tools/build-editorial.mjs
node qa/editorial.test.mjs
node qa/catalog.test.mjs
node qa/seo.test.mjs
node qa/grace-series.test.mjs
git diff --check
```

파일이 없어졌거나 현재 규칙에 맞지 않으면 이유를 확인해 현재 검사로 대체한다. 테스트가 특정 분류가 비어 있다고 가정하는 등 새 콘텐츠와 충돌하면 동작을 보존하는 일반적인 검증으로 고치며, 실패를 숨기기 위해 검사를 제거하지 않는다.

기존 글의 slug·내용·사진·분류가 유지됐는지 전후 비교한다. 신규/수정된 글의 제목·canonical·메타 설명·JSON-LD·성경/출처·모바일 화면·내부 링크·이미지 로드·첨부 자료를 확인한다. 청년 설교는 `청년 설교` 필터와 관리자 선택, 실제 본문의 초안 표시도 확인한다.

2026-11-20 공개 사이트는 GitHub Pages의 `main` 브랜치 루트 배포였다. 현재 설정을 확인한 뒤 해당 방식으로 발행한다. `main` push 후 배포가 실제 커밋으로 성공했는지 확인하고, 새 글·사진·자료의 공개 URL 응답과 메인/칼럼 반영을 확인한다. 유효한 스킬 검증이나 로컬 빌드 성공은 공개 게시 성공을 뜻하지 않는다.

Git 전송이 네트워크/HTTP 오류로 실패하면 먼저 원격 커밋을 확인해 중복·불확실한 재시도를 피한다. 필요 시 일회성 HTTP/1.1과 전송 버퍼 조정으로 같은 정상 push를 재시도할 수 있으나, force push로 우회하지 않는다. 최신 원격과 충돌하면 안전한 통합을 우선한다.
