# SO DO NOT FEAR 선교 글쓰기

## 목적과 독자

선교사, 현지 사역자, 선교를 준비하는 사람과 지원 교회에 실제 도움이 되는 한국어 콘텐츠를 만든다. 기술·언어·교육·운영의 어려움을 줄이고 말씀과 은혜, 지역교회와 이웃의 돌봄에 연결한다. 현지 교회와 주민의 판단·문화·주도권을 존중한다.

## 요청 해석

- 명시한 카테고리와 수량을 우선한다. 수량 생략 시 **지정한 카테고리마다 2편**, 요청한 경우 3편으로 한다. 모든 카테고리에 자동으로 2~3편씩 발행하지 않는다.
- 카테고리가 없으면 기존 글의 부족한 주제를 살펴 적절한 기존 분류 **하나**를 선택하고 그 선택을 알린다.
- `올려줘`, `게시해줘`, `업데이트해줘`는 해당 요청의 원고·사진·필요 자료·검증·커밋·배포·실제 확인까지 포함한다. 이미 허용된 범위의 게시를 다시 확인받으며 중단하지 않는다. 도구의 별도 승인 요구는 따른다.
- `초안만`은 글과 필요한 미리보기만 준비하고 공개 게시·배포하지 않는다.
- 같은 날 재시도라면 원격 발행 내역과 요청 수량을 확인해 중복 게시를 막는다. 사용자가 명시한 추가 발행까지 막지는 않는다.
- 등록은 매일 자동 실행을 뜻하지 않는다. 예약·외부 유료 API·결제 설정은 별도로 요청할 때만 다룬다.
- 이번 요청이 **스킬 등록/수정 자체**라면 사이트를 변경하거나 예시 글을 실제 게시하지 않는다.

## 작성 원칙

- 기존 제목뿐 아니라 본문·성경 본문·적용을 살펴 중복을 피한다. 기존 글 보완이 적합하면 그 이유와 신규/수정 수량을 구분한다.
- 글마다 대상 독자, 구체적 어려움, 읽은 뒤 할 수 있는 행동을 정한다. 추상적인 격려나 검색 키워드 나열에 머물지 않는다.
- 성경의 문맥, 하나님의 주권, 그리스도의 십자가와 부활, 은혜로 받는 구원과 감사의 순종을 중심에 둔다. 기술과 선교 실적을 구원의 능력·자격처럼 말하지 않는다.
- 쉬운 한국어와 차분하고 따뜻한 어조를 쓴다. 개혁주의 용어를 나열하거나 다른 전통을 비하하지 않는다. 기다림·실패·쉼을 숨기지 않고 성과 압박을 더하지 않는다.
- 가짜 간증·목회 경험·현장 사례·후기·통계·출처·실명 저자·감수 이력을 만들지 않는다. 가상 상황은 `실천 예시` 또는 `가상 예시`라고 밝힌다.
- 선교사의 신원·현지 위치, 비공개 상담·기도제목과 사역 자료의 공개 범위를 확인한다. 입력·공유할 필요가 없는 민감 정보는 쓰지 않는다.
- 성경 장절과 사용 번역본을 확인하고 직접 인용·요약·적용을 구분한다. 신앙고백은 장/문답 번호와 공식 출처를 확인한다. 인용 저작권과 분량을 존중한다.
- 기능·가격·정책 등 변하는 사실은 최신 공식 원문을 확인한다. 모르는 사실을 단정하지 말고 검증 가능한 범위로 조정한다.

### 일반 선교 칼럼

기본 약 1,200~2,500자에서 내용에 맞춰 조정한다. 준비물, 실행 순서, 요청 예시, 확인 방법과 문제 해결 중 독자에게 필요한 내용을 제공한다. 실무에 유익한 빈 양식은 실제 파일로 만들고 연결한다. 묵상 글에는 문맥·은혜·구체적 적용과 나눔 질문을 연결한다. 모든 글에 같은 틀을 강요하지 않는다.

### 청년 설교

`청년 설교`, 청년을 위한 설교문, 또는 그 카테고리의 글 요청이면 [청년 설교 작성 기준](references/youth-sermons.md)을 읽고 적용한다. 기본 수량은 위와 같고 설교 본문은 약 3,000~5,000자로 작성한다. **‘AI 작성 도움을 받은 설교문 초안’** 표시를 실제 본문에 넣는다. 이 표시는 공개 게시를 중단하는 승인 절차가 아니다.

## 이미지

글마다 내용을 돕는 잔잔한 Unsplash 사진을 고른다. 부드러운 빛과 파스텔 톤, 자연·길·공간·책·일상 풍경을 활용하되 같은 사진을 습관적으로 반복하지 않는다.

- 사진 원본 페이지에서 **무료 Unsplash License**를 확인한다. Unsplash+나 별도 유료 이미지는 제외한다. 조건을 확인하지 못하면 다른 사진이나 기존 검증 사진을 사용한다.
- 사진가·원본 주소·라이선스·확인일을 기록하고 글에 출처를 표시한다. 사진에 실제 보이는 내용을 대체 텍스트로 적는다.
- 자료 사진을 실제 사역 현장이나 간증 당사자로 소개하지 않는다. 식별되는 사람을 죄·중독·실패 등 부정적인 사례와 연결하지 않는다.
- 기기별 구도·용량·읽기 흐름을 확인한다. 기존 사진과 출처는 유지한다.
- 브라우저 작업에는 사용 가능한 ego-browser 스킬을 먼저 읽고 따른다. Unsplash API를 새로 연결한다면 공식 API의 핫링크·다운로드 이벤트·출처 규칙을 확인하고 준수한다. API 이용 조건과 일반 다운로드 라이선스를 혼동하지 않는다.

## 사이트 반영과 보존

게시 또는 원고를 사이트 형식으로 준비할 때 [사이트 원본·배포 절차](references/site-workflow.md)를 읽는다. 원격 최신 콘텐츠가 공개 상태의 기준이다. 작업 폴더가 오래되었거나 변경 중이면 그대로 덮어쓰지 않는다.

- 기존 카테고리·글·사진·자료·관리자 기능을 보존한다. ‘청년 설교’는 해당 작업을 수행할 때 목록에 없으면 한 번만 추가한다.
- 칼럼 분류, 관리자 선택, 메인 추천·최신 노출을 함께 확인한다. 추천에서 밀려난 글을 삭제하거나 비공개로 만들지 않는다.
- 실제 현재 날짜로 발행일을 기록한다. 수정은 최초 발행일을 보존하고 실제 수정일을 표시한다. 같은 날짜의 정렬도 확인한다.
- 제목·설명·canonical·사이트맵·구조화 데이터를 사실과 일치시키고 관련 글과 가이드로 연결한다. 검색 순위·색인·AI 인용을 보장하지 않는다.
- 게시 요청에서는 필요한 검증을 거쳐 배포 완료와 실제 새 URL·사진·자료·메인 반영을 확인한다. 초안/커밋/배포/색인 상태를 구분한다.
- 재시도는 실패 원인을 확인한 범위에서만 한다. 동시 수정과 충돌이 반복되어 안전하게 통합할 수 없다면 원고를 보존하고 구체적 남은 상태를 보고한다. 강제 push로 우회하지 않는다.

## 보고와 요청 예시

최종 보고는 카테고리별 신규·보완 수량, 대표 글/칼럼 링크, 사진·자료 수, 기존 내용 보존, 실제 배포 확인과 미해결 항목만 간결하게 정리한다. 완료하지 않은 작업을 완료로 표현하지 않는다.

요청 예시:
- `$sodonotfear-mission-editor로 AI·IT 선교 글 2편 올려줘. 기술 전수와 번역을 주제로 해줘.`
- `$sodonotfear-mission-editor로 청년 설교 2편 올려줘. 비교와 은혜를 다뤄줘.`
- `$sodonotfear-mission-editor로 운영 노하우 2편과 청년 설교 2편을 사진과 함께 게시하고 배포까지 확인해줘.`
- `$sodonotfear-mission-editor로 실패와 소명을 다루는 청년 설교 1편, 초안만 작성해줘.`
